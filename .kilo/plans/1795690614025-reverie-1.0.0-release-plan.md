# Reverie Planner 1.0.0 — Release Plan

## Goal / definition of done
Ship a trustworthy, local-first Notion replacement tagged `v1.0.0`: all P0/P1 workflows work offline without an AI account; data survives restart and forward-only migration; import/export, templates, favorites/recent, complete property/view editors, large-data pagination with a reproducible benchmark, and accessibility/keyboard/responsive acceptance are done; Windows/macOS/Linux portable packages produced by CI; release notes and parity/verification docs distinguish verified vs partial. A green build alone is not completion.

## Current verified state (evidence in repo)
- P0 data-trust DONE and pushed on `kilo/even-lotus-ijz` (commit `19f1304`): `decodeJSONBody` normalization for settings/providers/ping, query-plan index guards, rich synthetic v6/v7 migration tests. `go vet` + `go test ./...` pass (Go 1.26.0). Checklist 11/35 (no boxes checkable without Windows CI / real backups).
- In-progress (uncommitted working tree at plan time): favorites/recent pages backend (`page_favorites.go`, routes `/api/pages/favorites`, `/api/pages/recent`, tests passing) persisted in `app_state`. Needs commit + frontend UI.
- Existing: nested pages + BlockNote, 5 DB views, typed filters/sort, record pages, trash/restore, SQLite snapshot backup, atomic TSV bulk edit, optional AI providers.

## Hard release blockers (owner decisions required; cannot be fabricated by an agent)
1. Real historical v6/v7 production `.db` backups (desensitized) to satisfy migration acceptance. Synthetic fixtures do not count.
2. SHA-matched Windows CI run (Go tests, build, lint, Playwright, launcher start/stop, packaging) on the release commit.
3. macOS manual acceptance on real hardware; macOS signing/notarization (currently unsigned) — accept as documented limitation or complete.
4. Manual accessibility/keyboard/screen-reader acceptance on Windows and macOS.
Until 1–4 are satisfied, the artifact must be labeled a release candidate, not a certified 1.0.0.

## Ordered workstreams

### W1 — Finish favorites/recent (commit + UI)
- Commit the backend slice (tests green).
- Frontend `App.tsx`: load `/api/pages/favorites` and `/api/pages/recent`; render Favorites and Recent sections in the sidebar; toggle favorite on the current page; record a recent view when a page opens; clear-recent action.
- Validate: `npm run build`, `npm run lint`, Playwright spec for favorite toggle + recent ordering across reload.

### W2 — Templates
- Backend: `templates` via `app_state` (JSON list of {id,name,title,content,icon}) with GET/POST/DELETE `/api/templates`; creating a page from a template = existing page POST seeded with template content.
- Frontend: template picker in the new-page flow; "save as template" on a page.
- Tests: Go handler tests + Playwright create-from-template persistence.

### W3 — Markdown import/export (+ Notion-flavored Markdown)
- Backend: `GET /api/pages/{id}/export?format=md` returns Markdown (title + BlockNote→MD); `POST /api/pages/import` accepts `{title, markdown}` and creates a page (MD→BlockNote blocks). Reuse existing block model; no cloud deps.
- Frontend: Export/Import menu items on a page and workspace.
- Tests: Go round-trip (export→import→export stable), Playwright import creates page.

### W4 — Scale: pagination/virtualization + 10k benchmark
- Backend `handleDBRecords` GET: accept `limit`/`offset`; when `limit` present return `{records,total,limit,offset}` (backward-compatible bare array when absent); add `COUNT(*)` with same `deleted_at IS NULL` predicate; ensure index `idx_db_records_live` used (extend `db_query_plan_test.go`).
- Frontend `DatabaseView.tsx`: fetch pages of records; windowed/virtualized table rendering.
- Benchmark: `db_benchmark_test.go` seeds 10,000 records, records wall time/memory/`EXPLAIN QUERY PLAN`, writes results to `docs/BENCHMARK.md` with hardware notes. Acceptance: documented reproducible numbers (not a fixed threshold).

### W5 — Engineering & accessibility
- Split `DatabaseView.tsx` into typed API/model/view components; remove accidental `any` (App.tsx `searchResults`, `pendingApprovals`, theme casts); centralize request status/loading/error/conflict retry.
- Reduce oxlint warnings toward 0; keep the lazy editor chunk.
- WCAG: keyboard/focus/ARIA for sidebar, dialogs, table cells; narrow-window responsive; no control hidden by layout.
- Validate: `npm run lint` (warnings down), `npm run build`, new Playwright keyboard/a11y regressions.

### W6 — Database finish
- Full property editor (all types incl. person/file/timestamps read-only rules), view manager (rename/duplicate/delete/reorder, inline/linked), Gallery cover + property selection, List actions.
- Reciprocal/indexed relation lifecycle with deletion semantics + rollback; explicit 409 conflict UX for property/version/linked-view with draft preservation (two-context Playwright).
- Tests: Go lifecycle/rollback + Playwright per feature; keep all existing assertions.

### W7 — Release engineering
- Bump `appVersion` to `1.0.0`; update README/RELEASE docs; regenerate parity matrix.
- CI: Windows/macOS/Linux build + Playwright + launcher + packaging on the release SHA; publish portable assets.
- Tag `v1.0.0` only after W1–W6 + blockers 1–4 satisfied (or owner-accepted limitations recorded).
- Update `DATABASE_COMPLETION_PLAN.md` checkboxes only with code + SHA-matched CI evidence.

## Validation (each slice)
- Backend: `go test ./...`, `go vet ./src/backend`.
- Frontend: `cd src/frontend && npm ci && npm run lint && npm run build && npx playwright install chromium && npm run test:e2e`.
- Record exact commit SHA + CI run per claim; never weaken existing assertions.

## Risks
- Migration-count tests hardcode `10`; any new numbered migration must update `latestSupportedSchemaMigration`, the legacy tests, and version-guard tests together (favor `app_state` JSON to avoid migrations where possible).
- Changing `/api/db/records` response shape breaks the UI — keep legacy bare-array mode.
- Large frontend refactors risk regressions; land behind Playwright coverage.
- Cross-platform build ≠ manual acceptance; macOS signing is a distribution gap.
